## CRITICAL: File-Name Mismatch Between Code and Disk

The codebase references `fabrica-*.png` filenames, but the actual files on disk are named `orca-*.png`. This is a **build-breaking mismatch** — at runtime the app cannot find the watercolor/blue icon variants or the macOS tray template.

| Code reference (imports) | Actual file on disk | Status |
|---|---|---|
| `resources/app-icons/fabrica-watercolor.png` | `resources/app-icons/orca-watercolor.png` | **BROKEN** |
| `resources/app-icons/fabrica-blue.png` | `resources/app-icons/orca-blue.png` | **BROKEN** |
| `resources/tray/fabrica-menu-barTemplate.png` | `resources/tray/orca-menu-barTemplate.png` | **BROKEN** |
| `resources/tray/fabrica-menu-barTemplate@2x.png` | `resources/tray/orca-menu-barTemplate@2x.png` | **BROKEN** |

**Affected source files:**

- `src/main/app-icon.ts:11-14` — imports watercolor and blue icons via `fabrica-*` paths
- `src/main/tray/system-tray.ts:2-3` — imports tray template via `fabrica-menu-bar*` paths
- `src/renderer/src/components/settings/AppIconSelector.tsx:4-5` — imports watercolor and blue via `fabrica-*` paths
- `src/main/app-icon.test.ts:36-48` — test mocks use `fabrica-*` paths (tests pass because mocks mask the missing files, but runtime is broken)

**Root cause:** The `orca-*.png` files are likely legacy Orca-brand assets that were never renamed to `fabrica-*`, or the code was updated to reference `fabrica-*` without renaming the files.
